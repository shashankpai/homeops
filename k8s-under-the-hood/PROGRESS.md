#### 3. Infrastructure as Code ✅

**Terraform** (Proxmox VM provisioning):
- `lab/terraform/providers.tf` — Proxmox provider with API token authentication
- `lab/terraform/variables.tf` — All configurable parameters (IPs, node placement, resources, credentials)
- `lab/terraform/main.tf` — 3 VM resources distributed across 3 physical hosts:
  - Master: 2 vCPU, 6GB RAM, 30GB disk (192.168.1.81) on pve4/.47
  - Worker 1: 2 vCPU, 4GB RAM, 30GB disk (192.168.1.82) on pve2/.87
  - Worker 2: 2 vCPU, 4GB RAM, 30GB disk (192.168.1.83) on pve3/.25
  - NO VMs on pve/.48 (main node)
  - Created from official Ubuntu 24.04 cloud image (downloaded per-node by Terraform — no template VM needed)
  - Static IPs via cloud-init
  - Generates Ansible inventory automatically
- `lab/terraform/outputs.tf` — Outputs IPs, Kubernetes API endpoint, kubeconfig path

**Ansible** (K3s installation):
- `lab/ansible/k3s-cluster.yml` — K3s v1.36.3+k3s1 installation playbook
  - Prepares all nodes (swap, packages, hostname)
  - Installs K3s master (server)
  - Installs K3s workers (agents)
  - Waits for all nodes to be Ready
  - Copies kubeconfig to ubuntu user
  - Installs investigation tools: jq, cgroup-tools, linux-tools-common
- `lab/ansible/inventory.ini.tpl` — Inventory template (generated by Terraform)
- `lab/ansible/group_vars/all.yml` — K3s configuration
- `lab/ansible/requirements.yml` — Ansible collections

#### 4. Orchestration Scripts ✅

**lab/scripts/setup.sh** — Complete lab setup (one-time):
1. Checks prerequisites (terraform, ansible, kubectl, jq)
2. Generates SSH keys if needed
3. Verifies Proxmox API credentials
4. Runs `terraform apply` to provision VMs
5. Waits for VMs to boot (2-3 minutes)
6. Verifies SSH connectivity to all VMs
7. Runs Ansible playbook to install K3s
8. Copies kubeconfig to `~/.kube/config-k8suth`
9. Deploys observability stack (Prometheus, Grafana, etc.)
10. Waits for observability pods to be ready

**lab/scripts/verify.sh** — Lab health checks:
- Verifies kubeconfig exists
- Checks Kubernetes cluster connectivity
- Verifies all 3 nodes are Ready
- Checks monitoring namespace exists
- Checks observability pods are running
- Verifies Prometheus targets are UP
- Checks key metrics are available

**lab/scripts/teardown.sh** — Lab destruction:
- Prompts for confirmation (safety)
- Runs `terraform destroy`
- Cleans up kubeconfig

#### 5. Makefile ✅
- `make setup` — Run lab setup
- `make verify` — Verify lab health
- `make demo-ep01` — Run Episode 1 demo
- `make cleanup-ep01` — Clean up Episode 1
- `make teardown` — Destroy lab
- `make help` — Show help

#### 6. Configuration ✅
- `.gitignore` — Excludes Terraform state, SSH keys, kubeconfig, environment files

## Technical Highlights

### Security
- API token authentication (not hardcoded passwords)
- SSH keys stored locally (not committed to git)
- kubeconfig stored locally (not committed to git)

### Reproducibility
- All infrastructure defined as code (Terraform)
- All configuration defined as code (Ansible)

- node-exporter (host metrics)

## How to Use

### First Time Setup

1. **Verify prerequisites**:
   ```bash
   cd /Users/Shashank.Pai/Proxmox/homeops/k8s-under-the-hood
   cat docs/prerequisites.md
   ```

2. **Set Proxmox credentials**:
   ```bash
   export PM_API_TOKEN_ID="root@pam!k8s-under-the-hood"
   export PM_API_TOKEN_SECRET="your-token-secret"
   # OR
   source ~/.proxmox-env
   ```

3. **Provision the lab** (15-20 minutes):
   ```bash
   make setup
   ```

4. **Verify everything is healthy**:
   ```bash
   make verify
   ```

### Running Episodes

```bash
# Run Episode 1
make demo-ep01

# Clean up Episode 1 (keep lab running)
make cleanup-ep01

# Run Episode 2 (when ready)
make demo-ep02

# Clean up Episode 2
make cleanup-ep02
```

### Accessing the Lab

```bash
# Set kubeconfig
export KUBECONFIG=~/.kube/config-k8suth

# Check cluster
kubectl get nodes

# SSH to master
ssh -i lab/ssh/id_rsa ubuntu@192.168.1.81

# Access Prometheus
kubectl port-forward -n monitoring svc/prometheus 9090:9090
# Open http://localhost:9090

# Access Grafana
kubectl port-forward -n monitoring svc/grafana 3000:3000
# Open http://localhost:3000 (admin/admin)
```

### Destroying the Lab

```bash
make teardown
```
